# Configuration Packages

Shared configuration for ESLint and TypeScript across the monorepo.

## Overview

Configuration packages ensure consistent code style, linting rules, and TypeScript settings across all apps and packages.

**Packages**:
- `@uwdsc/eslint-config` - ESLint flat configs (ESM)
- `@uwdsc/typescript-config` - TypeScript configurations

## ESLint Config (`@uwdsc/eslint-config`)

Shared ESLint **flat config** (ESM), built on `typescript-eslint`. Each variant is a named export (an array of config objects), not a default export - spread it into your own `eslint.config.js`/`.mjs`.

**Location**: `packages/eslint-config/`

### Available Configurations

#### Base Configuration

For general TypeScript projects (no React):

```javascript
// packages/eslint-config/base.js
import js from "@eslint/js";
import eslintConfigPrettier from "eslint-config-prettier";
import onlyWarn from "eslint-plugin-only-warn";
import turboPlugin from "eslint-plugin-turbo";
import tseslint from "typescript-eslint";

export const config = [
  js.configs.recommended,
  eslintConfigPrettier,
  ...tseslint.configs.recommended,
  {
    plugins: { turbo: turboPlugin },
    rules: { "turbo/no-undeclared-env-vars": "warn" },
  },
  { plugins: { onlyWarn } },
  { ignores: ["dist/**"] },
];
```

**Usage:**

```javascript
// packages/common/eslint.config.js
import { config } from "@uwdsc/eslint-config/base";

export default config;
```

#### Next.js Configuration

For Next.js applications - layers React, React Hooks, and `@next/eslint-plugin-next` on top of the base config:

```javascript
// packages/eslint-config/next.js - exported as "@uwdsc/eslint-config/next-js"
import pluginNext from "@next/eslint-plugin-next";
import pluginReact from "eslint-plugin-react";
import pluginReactHooks from "eslint-plugin-react-hooks";
import { config as baseConfig } from "./base.js";

export const nextJsConfig = [
  ...baseConfig,
  // ...React + @next/eslint-plugin-next rules (see the source for the full list)
];
```

**Usage:**

```javascript
// apps/web/eslint.config.mjs
import { nextJsConfig } from "@uwdsc/eslint-config/next-js";

export default [
  ...nextJsConfig,
  {
    ignores: [".next/**", ".turbo/**", ".vercel/**", "node_modules/**", "next-env.d.ts"],
  },
];
```

> Note the export path is **`next-js`**, not `next` - `"@uwdsc/eslint-config/next-js"`.

#### React Internal Configuration

For React component libraries (used by `packages/ui`):

```javascript
// packages/eslint-config/react-internal.js
import pluginReact from "eslint-plugin-react";
import pluginReactHooks from "eslint-plugin-react-hooks";
import { config as baseConfig } from "./base.js";

export const config = [
  ...baseConfig,
  pluginReact.configs.flat.recommended,
  // ...react-hooks rules, browser globals
];
```

**Usage:**

```javascript
// packages/ui/eslint.config.js
import { config } from "@uwdsc/eslint-config/react-internal";

export default config;
```

### Package exports

```json
{
  "exports": {
    "./base": "./base.js",
    "./next-js": "./next.js",
    "./react-internal": "./react-internal.js"
  }
}
```

## TypeScript Config (`@uwdsc/typescript-config`)

Shared TypeScript compiler configurations, referenced by file path (this package has no `exports` map - it's consumed as raw JSON files).

**Location**: `packages/typescript-config/`

### Available Configurations

#### Base Configuration

```json
// packages/typescript-config/base.json
{
  "compilerOptions": {
    "declaration": true,
    "declarationMap": true,
    "esModuleInterop": true,
    "incremental": false,
    "isolatedModules": true,
    "jsx": "react-jsx",
    "lib": ["dom", "dom.iterable", "esnext"],
    "module": "ESNext",
    "moduleDetection": "force",
    "moduleResolution": "bundler",
    "noUncheckedIndexedAccess": true,
    "resolveJsonModule": true,
    "skipLibCheck": true,
    "strict": true,
    "target": "ES2022"
  }
}
```

**Usage:**

```json
// tsconfig.json
{
  "extends": "@uwdsc/typescript-config/base.json"
}
```

#### Next.js Configuration

```json
// packages/typescript-config/nextjs.json
{
  "extends": "./base.json",
  "compilerOptions": {
    "plugins": [{ "name": "next" }],
    "module": "ESNext",
    "moduleResolution": "Bundler",
    "allowJs": true,
    "jsx": "preserve",
    "noEmit": true
  }
}
```

**Usage** (each app adds its own path aliases and includes):

```json
// apps/web/tsconfig.json
{
  "extends": "@uwdsc/typescript-config/nextjs.json",
  "compilerOptions": {
    "noImplicitAny": false,
    "paths": {
      "@/*": ["./*"],
      "@uwdsc/ui": ["../../packages/ui/src/index.ts"],
      "@uwdsc/core": ["../../packages/server/core/src/index.ts"],
      "@uwdsc/db": ["../../packages/server/db/src/config/supabase.ts"]
    },
    "plugins": [{ "name": "next" }]
  },
  "include": ["next-env.d.ts", "next.config.ts", "types/**/*.d.ts", "**/*.ts", "**/*.tsx", ".next/types/**/*.ts"],
  "exclude": ["node_modules", ".next", ".turbo", ".vercel"]
}
```

> Several `@uwdsc/*` workspace packages (`@uwdsc/db` in particular) are resolved via these per-app `paths` aliases rather than the package's own `exports` map - see [Monorepo Structure](/architecture/monorepo) for why.

#### React Library Configuration

```json
// packages/typescript-config/react-library.json
{
  "extends": "./base.json",
  "compilerOptions": {
    "jsx": "react-jsx"
  }
}
```

**Usage:**

```json
// packages/ui/tsconfig.json
{
  "extends": "@uwdsc/typescript-config/react-library.json"
}
```

## Usage Examples

### Setting Up a New App

```json
// apps/new-app/package.json
{
  "devDependencies": {
    "@uwdsc/eslint-config": "workspace:*",
    "@uwdsc/typescript-config": "workspace:*"
  }
}
```

```javascript
// apps/new-app/eslint.config.mjs
import { nextJsConfig } from "@uwdsc/eslint-config/next-js";

export default nextJsConfig;
```

```json
// apps/new-app/tsconfig.json
{
  "extends": "@uwdsc/typescript-config/nextjs.json",
  "include": ["next-env.d.ts", "**/*.ts", "**/*.tsx"],
  "exclude": ["node_modules"]
}
```

```json
// packages/new-package/package.json
{

```

```javascript
// packages/new-package/eslint.config.js

export default config;
```

```json
// packages/new-package/tsconfig.json
{
  "extends": "@uwdsc/typescript-config/base.json"

```

## Customization

### Adding Custom Rules

```javascript
// apps/web/eslint.config.mjs
import { nextJsConfig } from "@uwdsc/eslint-config/next-js";

export default [
  ...nextJsConfig,
  {
    rules: {
      "no-console": "warn",
    },
  },
];
```

### Overriding TypeScript Options

```json
// apps/web/tsconfig.json
{
  "extends": "@uwdsc/typescript-config/nextjs.json",
  "compilerOptions": {
    "strict": false,
    "paths": {
      "@/*": ["./"]
    }
  }
}
```

## Running Linters

```bash
pnpm lint         # turbo lint - eslint --max-warnings 0 in every package (warnings fail)
pnpm check-types  # turbo check-types - tsc --noEmit across the workspace
```

## Best Practices

### ✅ Do

- Use shared configs for consistency
- Override rules sparingly, and only in the consuming app/package's own config
- Keep custom rules to a minimum
- Run `pnpm lint` and `pnpm check-types` before committing

### ❌ Don't

- Disable important rules
- Skip type checking
- Ignore linter warnings - `pnpm lint` runs with `--max-warnings 0`, so a warning fails CI
- Bypass linters

## Troubleshooting

### ESLint Errors

If you get unexpected ESLint errors, restart your editor's ESLint server (VS Code: Cmd/Ctrl + Shift + P -> "ESLint: Restart ESLint Server").

### TypeScript Errors

```bash
# Re-check types across the workspace
pnpm check-types

# Restart TypeScript server in VS Code
# Cmd/Ctrl + Shift + P -> "TypeScript: Restart TS Server"
```
