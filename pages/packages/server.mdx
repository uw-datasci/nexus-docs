# Server Packages

Backend services and data layer: `@uwdsc/db`, `@uwdsc/core`, and `@uwdsc/admin`.

## Overview

The `packages/server/` directory contains three sub-packages. There is **no Prisma**; data access uses **postgres.js** (via `@uwdsc/db`) and **Supabase** for auth and storage.

**Sub-packages**:

- **@uwdsc/db** - Database connection, Supabase clients, BaseRepository, migrations
- **@uwdsc/core** - Shared services and repositories used by web and admin apps
- **@uwdsc/admin** - Admin-only services (e.g. member management for admin dashboard)

## Structure

```
packages/server/
├── db/              # @uwdsc/db
│   └── src/
│       ├── config/       # connection, supabase, base.repository
│       └── migrations/   # db-migrate SQL files
├── core/            # @uwdsc/core
│   └── src/
│       ├── modules/      # auth/, profile/, application/, team/, events/, membership/, file/, contact/
│       │                 #   each: <domain>.service.ts + <domain>.repository.ts (extends BaseRepository)
│       ├── http/         # withRaftRoute.ts - Raft route wrapper (@uwdsc/core/http)
│       └── ...
└── admin/           # @uwdsc/admin
    └── src/              # modules/ - admin-specific services (e.g. profileService for members)
```

## @uwdsc/db

**Purpose**: Database connection, Supabase clients, base repository, migrations.

**Exports**:

- `@uwdsc/db/connection` - Postgres `sql` (postgres.js)
- `@uwdsc/db/supabase` - `createSupabaseBrowserClient`, `createSupabaseServerClient`, `createSupabaseMiddlewareClient`
- `@uwdsc/db/supabase/profile` - Supabase profile helpers
- `@uwdsc/db/base.repository` - `BaseRepository` (abstract class with protected `this.sql`)

The bare `@uwdsc/db` specifier used in app code (`import { createSupabaseServerClient } from "@uwdsc/db"`) isn't one of these package exports - it's a `paths` alias each app's `tsconfig.json` points at `config/supabase.ts`.

**Tech**: postgres.js (Supabase Transaction Pooler), Supabase JS/SSR, db-migrate. Run migrations from root: `pnpm migrate`, `pnpm migrate:down`, `pnpm migrate:create <name>`.

## @uwdsc/core

**Purpose**: Shared services and repositories used by **web** and **admin** apps.

**Exports**:

- `@uwdsc/core` - service classes and **singleton instances**: `profileService`, `applicationService`, `teamService`. `AuthService` and `ResumeService` require a Supabase client and are created per-request in each app's `lib/services.ts` via `createAuthService()` / `createResumeService()`.
- `@uwdsc/core/http` - `withRaftRoute`, the [Raft](/packages/raft) route wrapper used to build every `apps/web` API route.

```typescript
import { profileService, applicationService, teamService } from "@uwdsc/core";
import { AuthService, ResumeService } from "@uwdsc/core";
import { withRaftRoute } from "@uwdsc/core/http";
```

**Contents**:

- **Modules** (`src/modules/<domain>/`): auth, profile, application, team, events, membership, file, contact - each with a `<domain>.service.ts` and `<domain>.repository.ts`
- **Repositories**: Extend `BaseRepository` from `@uwdsc/db/base.repository`; use `this.sql` for queries
- **Dependencies**: `@uwdsc/db`, `@uwdsc/common`, `@uw-datasci/raft`

## @uwdsc/admin

**Purpose**: Admin-only services (e.g. profile/member listing and updates for the admin dashboard).

**Exports**: Admin-specific `profileService` (and related) for member management, organized the same way as `@uwdsc/core` (`src/modules/<domain>/`: application, hiring, membership, events, email, integration, raft).

```typescript
import { profileService } from "@uwdsc/admin";
```

**Used by**: `apps/admin` API routes only, via the guards in `apps/admin/guards`. **Dependencies**: `@uwdsc/core`, `@uwdsc/db`, `@uwdsc/common`.

## Usage

### In API Routes (web or admin)

Wrap every route with [Raft](/packages/raft) - `withRaftRoute` directly in `apps/web`, or a guard (`withAuth`/`withAdmin`) that includes it in `apps/admin`:

```typescript
// apps/web/app/api/profile/route.ts
import { RaftResponse } from "@uw-datasci/raft";
import { withRaftRoute } from "@uwdsc/core/http";
import { profileService } from "@uwdsc/core";

export const GET = withRaftRoute(async () => {
  const profile = await profileService.getProfileByUserId(user.id);
  return RaftResponse.ok(profile);
});
```

```typescript
// apps/admin/app/api/members/route.ts
import { RaftResponse } from "@uw-datasci/raft";
import { withAdmin } from "@/guards/withAdmin";
import { profileService } from "@uwdsc/admin";

export const GET = withAdmin(async () => {
  const members = await profileService.listMembers();
  return RaftResponse.ok(members);
});
```

### Auth and resume (per-request)

Create Supabase-backed services in the app:

```typescript
// apps/web/lib/services.ts
import { createSupabaseServerClient } from "@uwdsc/db";
import { AuthService, ResumeService } from "@uwdsc/core";

export async function createAuthService() {
  const supabase = await createSupabaseServerClient();
  return new AuthService(supabase);
}

export async function createResumeService() {
  const supabase = await createSupabaseServerClient();
  return new ResumeService(supabase);
}
```

### Repository layer

Repositories extend `BaseRepository` and use `this.sql` (postgres.js):

```typescript
import { BaseRepository } from "@uwdsc/db/base.repository";

export class ProfileRepository extends BaseRepository {
  async findByUserId(userId: string) {
    const rows = await this.sql`SELECT * FROM profiles WHERE id = ${userId}`;
    return rows[0] ?? null;
  }
}
```

## Database migrations

Migrations live in `packages/server/db`. From repo root:

- `pnpm migrate` - apply
- `pnpm migrate:down` - rollback last
- `pnpm migrate:create <name>` - create new migration
- `pnpm migrate:check` - status

## Best practices

### Do

- Use services from `@uwdsc/core` or `@uwdsc/admin` in API routes
- Use singletons (`profileService`, `applicationService`, `teamService`) where the service is stateless
- Create AuthService/ResumeService per-request via `lib/services.ts`
- Extend `BaseRepository` from `@uwdsc/db/base.repository` for new repositories
- Wrap routes with `withRaftRoute` from `@uwdsc/core/http` (or an admin guard) and use `RaftResponse` from `@uw-datasci/raft`

### Don’t

- Import server packages in React components - use client API functions from `lib/api/`
- Put business logic in API routes or repositories
- Access the database directly from API routes
- Assume Prisma - the project uses postgres.js and Supabase
