# Common Package

Shared types and utilities used across the monorepo (web, admin, and server packages).

## Overview

The `@uwdsc/common` package holds:

- **Types** - Domain entities, API request/response types, shared enums, and error types
- **Utils** - filterPartialUpdate and other helpers
- **Constants** - Role/faculty/membership enums and helpers, and shared route paths

**Location**: `packages/common/`

**Exports**:

- `@uwdsc/common/types` - All shared types
- `@uwdsc/common/utils` - filterPartialUpdate and other utilities
- `@uwdsc/common/constants` - Roles (`isAdmin`, `readRoleClaims`, `ADMIN_ROLES`), faculty, membership, application, and route constants

## Types (`@uwdsc/common/types`)

Import types from `@uwdsc/common/types` in apps and server code so both sides use the same definitions.

### Entities

Domain entities (often aligned with DB tables) in `packages/common/src/types/entities/`:

- **Application** - Application and related entity types
- **File** - File/resume types
- **Profile** - Profile entity
- **Membership** - Membership entity
- **Team** - Team entity

### API types

Request/response and API-layer types in `packages/common/src/types/api/`:

- **application** - Application API types (e.g. update payloads, autofill, position/answer inputs)

Use these in API routes, client `lib/api` functions, and services so request/response shapes stay in sync.

### Shared

Shared enums, errors, and common types in `packages/common/src/types/shared/`:

- **enums** - Shared enums (e.g. application-related)
- **errors** - `ApiError` class for consistent error handling
- **common** - Common utility types
- **auth** - Auth-related types

### Usage

```typescript
// In API routes, services, or client code
import type { UserProfile, UpdateProfileRequest } from "@uwdsc/common/types";
import type { ApplicationUpdatePayload } from "@uwdsc/common/types";
import { ApiError } from "@uwdsc/common/types";
```

When adding new API or entity types, add them under `packages/common/src/types/api/` or `entities/` and export from the corresponding `index.ts`.

## Constants (`@uwdsc/common/constants`)

Shared enums, role helpers, and route constants used by both apps and server code.

**Import**: `import { isAdmin, readRoleClaims, ADMIN_ROLES } from "@uwdsc/common/constants";`

- **roles** - `ROLE_VALUES`, `ROLE_LABELS`, `ADMIN_ROLES` (the set allowed into the admin app), `isAdmin(role)`, `isPres(role)`, `isAlum(role)`, `readRoleClaims(appMetadata)` (parses the role claims Supabase mirrors into `app_metadata`), `roleRequiresSubteam(role)`
- **faculty** - `FACULTY_VALUES`, `FACULTY_LABELS`
- **membership** - Membership-related enum values and labels
- **application** - Application-related constants
- **routes** - Shared path constants (e.g. `WEB_COMPLETE_PROFILE_PATH`)

Example - the admin `withAdmin` guard uses these directly to check a role from the Supabase session:

```typescript
import { isAdmin, readRoleClaims } from "@uwdsc/common/constants";

const claims = readRoleClaims(user.app_metadata);
if (!isAdmin(claims.role)) return RaftResponse.forbidden("You must be admin to access");
```

## Utils (`@uwdsc/common/utils`)

> Looking for standardized API responses? That's [`RaftResponse`](/packages/raft) from `@uw-datasci/raft` now, not this package - `ApiResponse` was removed from `@uwdsc/common/utils` when the repo migrated to Raft.

### filterPartialUpdate

Builds safe partial-update payloads by keeping only defined, allowed keys. Useful for PATCH-style updates in repositories or services.

**Signature**:

```typescript
function filterPartialUpdate<T extends Record<string, unknown>>(
  data: T,
  allowedColumns: readonly string[],
): { filteredData: Record<string, string | boolean | null>; columns: string[] };
```

**Example**:

```typescript
import { filterPartialUpdate } from "@uwdsc/common/utils";

const allowed = ["name", "bio", "avatar"] as const;
const { filteredData, columns } = filterPartialUpdate(
  { name: "Jane", bio: "Dev", ignored: "x" },
  allowed,
);
// filteredData: { name: "Jane", bio: "Dev" }
// columns: ["name", "bio"]
```

## Dependencies

`@uwdsc/common` has **no runtime dependencies** of its own - it's pure types, constants, and utility functions, so it can be imported from client or server code without pulling anything else in. It is used by `@uwdsc/core`, `@uwdsc/admin`, and the web and admin apps.

## Best practices

### Do

- Define API and entity types in `@uwdsc/common/types` and import them in both client and server code
- Use `ApiError` from `@uwdsc/common/types` in services when throwing typed errors - `withRaftRoute` (see [Raft](/packages/raft)) translates it into the right HTTP status automatically
- Use the role helpers (`isAdmin`, `readRoleClaims`, `ADMIN_ROLES`) from `@uwdsc/common/constants` instead of re-deriving role checks
- Use `filterPartialUpdate` when building dynamic PATCH/update payloads from partial input

### Don't

- Define duplicate types in apps or server packages; add shared types to common
- Build standardized API responses here - that's `RaftResponse` from `@uw-datasci/raft` now
