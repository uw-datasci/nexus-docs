# Creating API Endpoints

Step-by-step guide to creating new API endpoints following our architecture.

## Overview

Creating a new API endpoint involves 6 steps:

1. Define TypeScript types
2. Create Zod validation schema
3. Create repository method
4. Create service method
5. Create API route (wrapped with [Raft](/packages/raft))
6. Create client API function

Let's create a complete example: **User Profile API**

## Step 1: Define Types

Define API types in the **common package** so they can be shared by apps and server packages. Add a new file under `packages/common/src/types/api/` (e.g. `profile.ts`), then export it from `packages/common/src/types/api/index.ts` (e.g. `export * from "./profile";`):

```typescript
// packages/common/src/types/api/profile.ts

export interface UserProfile {
  id: string;
  email: string;
  name: string;
  bio?: string;
  avatar?: string;
  createdAt: string;
}

export interface UpdateProfileRequest {
  name?: string;
  bio?: string;
  avatar?: string;
}

export interface UpdateProfileResponse {
  profile: UserProfile;
  message: string;
}
```

Import in apps and API code from `@uwdsc/common/types`:

```typescript
import type {
  UserProfile,
  UpdateProfileRequest,
  UpdateProfileResponse,
} from "@uwdsc/common/types";
```

## Step 2: Create Validation Schema

Create Zod schemas in `apps/web/lib/schemas/profile.ts`:

```typescript
// apps/web/lib/schemas/profile.ts
import { z } from "zod";

export const updateProfileSchema = z.object({
  name: z.string().min(2, "Name must be at least 2 characters").optional(),
  bio: z.string().max(500, "Bio must be less than 500 characters").optional(),
  avatar: z.string().url("Invalid avatar URL").optional(),
});

export type UpdateProfileInput = z.infer<typeof updateProfileSchema>;
```

## Step 3: Create Repository Method

Add database queries in `packages/server/core/src/modules/profile/profile.repository.ts` (each domain module holds its own `<domain>.repository.ts`). Repositories extend `BaseRepository` from `@uwdsc/db/base.repository` and use `this.sql` (postgres.js):

```typescript
// packages/server/core/src/modules/profile/profile.repository.ts
import { BaseRepository } from "@uwdsc/db/base.repository";

export class ProfileRepository extends BaseRepository {
  async findProfileByUserId(userId: string) {
    const rows = await this.sql`
      SELECT id, email, name, bio, avatar, created_at as "createdAt"
      FROM profiles WHERE id = ${userId}
    `;
    return rows[0] ?? null;
  }

  async updateProfile(userId: string, data: { name?: string; bio?: string; avatar?: string }) {
    // Build dynamic update with this.sql - see existing repos in core for patterns
    const updated = await this.sql`...`;
    return updated[0] ?? null;
  }

  async profileExists(userId: string): Promise<boolean> {
    const rows = await this.sql`
      SELECT 1 FROM profiles WHERE id = ${userId} LIMIT 1
    `;
    return rows.length > 0;
  }
}
```

## Step 4: Create Service Method

Add business logic in `packages/server/core/src/modules/profile/profile.service.ts`. For profile, the app already uses the shared `profileService` singleton from `@uwdsc/core`. If you add a new service:

```typescript
// packages/server/core/src/modules/profile/profile.service.ts
import { ProfileRepository } from "./profile.repository";
import { ApiError } from "@uwdsc/common/types";

export class ProfileService {
  private repository: ProfileRepository;

  constructor() {
    this.repository = new ProfileRepository();
  }

  /**
   * Get user profile
   */
  async getProfile(userId: string) {
    const profile = await this.repository.findProfileByUserId(userId);

    if (!profile) {
      throw new ApiError("Profile not found", 404, "PROFILE_NOT_FOUND");
    }

    return profile;
  }

  /**
   * Update user profile
   */
  async updateProfile(
    userId: string,
    data: {
      name?: string;
      bio?: string;
      avatar?: string;
    },
  ) {
    // Check if profile exists
    const exists = await this.repository.profileExists(userId);
    if (!exists) {
      throw new ApiError("Profile not found", 404, "PROFILE_NOT_FOUND");
    }

    // Validate avatar URL if provided
    if (data.avatar) {
      await this.validateAvatarUrl(data.avatar);
    }

    // Update profile
    const updated = await this.repository.updateProfile(userId, data);

    return {
      profile: updated,
      message: "Profile updated successfully",
    };
  }

  /**
   * Validate avatar URL
   */
  private async validateAvatarUrl(url: string) {
    // Check if URL is accessible
    try {
      const response = await fetch(url, { method: "HEAD" });
      if (!response.ok) {
        throw new Error("Invalid avatar URL");
      }
    } catch (error) {
      throw new ApiError("Avatar URL is not accessible", 400, "INVALID_AVATAR_URL");
    }
  }
}
```

## Step 5: Create API Routes

Create Next.js API routes in `apps/web/app/api/profile/`. Wrap every handler with **`withRaftRoute`** (`@uwdsc/core/http`) and build responses with **`RaftResponse`** (`@uw-datasci/raft`) instead of hand-building `NextResponse`. See [Raft](/packages/raft) for the full reference.

### Standardized responses (RaftResponse)

| Method                                       | Status | Use                                                            |
| --------------------------------------------- | ------ | --------------------------------------------------------------- |
| `RaftResponse.ok(data)`                       | 200    | Success with optional JSON body                                 |
| `RaftResponse.badRequest(message?, error?)`   | 400    | Validation or client error                                      |
| `RaftResponse.unauthorized(message?, error?)` | 401    | Not authenticated                                                |
| `RaftResponse.forbidden(message?, error?)`    | 403    | Authenticated but not allowed                                    |
| `RaftResponse.notFound(error?)`               | 404    | Resource not found                                               |
| `RaftResponse.json(data, status?, init?)`     | custom | Custom status or body shape                                      |
| `RaftResponse.text(body, contentType, status?)` | custom | Non-JSON response (e.g. an .ics calendar feed)                 |
| `RaftResponse.serverError(message?, error?)`  | 500    | **Async** - always `await` or `return` it from an async handler |

Response bodies follow a consistent shape: success uses the data you pass; errors use `{ error }` or `{ error, message }`.

```typescript
import { RaftResponse } from "@uw-datasci/raft";

// In a route:
return RaftResponse.ok({ profile, isComplete });
return RaftResponse.badRequest("Email is required");
return RaftResponse.notFound("Profile not found");
```

**You rarely need a manual `try/catch`.** `withRaftRoute` already catches anything thrown and quarantines it to Postgres as a clean `500`. Throw `ApiError` from `@uwdsc/common/types` (or any `Error`) and let the wrapper handle it; use explicit `RaftResponse.badRequest()` etc. only for expected 4xx outcomes you want to return directly.

### GET Profile Route

```typescript
// apps/web/app/api/profile/route.ts
import { RaftResponse } from "@uw-datasci/raft";
import { withRaftRoute } from "@uwdsc/core/http";
import { profileService } from "@uwdsc/core";
import { getCurrentUser } from "@/lib/auth";

export const GET = withRaftRoute(async () => {
  const user = await getCurrentUser();
  if (!user) return RaftResponse.unauthorized("Authentication required");

  const profile = await profileService.getProfileByUserId(user.id);
  if (!profile) return RaftResponse.notFound("Profile not found");

  return RaftResponse.ok(profile);
});
```

Note there's no `try/catch` - an unexpected throw (a DB failure, for example) is caught by `withRaftRoute`, quarantined, and turned into a `500` automatically.

### UPDATE Profile Route

```typescript
// apps/web/app/api/profile/route.ts (continued)
import { z } from "zod";
import type { NextRequest } from "next/server";
import { updateProfileSchema } from "@/lib/schemas/profile";

export const PATCH = withRaftRoute(async (request: NextRequest) => {
  const user = await getCurrentUser();
  if (!user) return RaftResponse.unauthorized("Authentication required");

  const body = await request.json();
  const validated = updateProfileSchema.parse(body); // throws z.ZodError -> quarantined 500

  const result = await profileService.updateProfile(user.id, validated);
  return RaftResponse.ok(result);
});
```

If you need Zod validation errors to come back as a `400` instead of a quarantined `500`, catch `z.ZodError` specifically and return `RaftResponse.badRequest(...)` - or throw a 4xx `ApiError`, which `withRaftRoute` maps without quarantining.

### In `apps/admin`: use a guard instead

`apps/admin` never calls `withRaftRoute` directly - its route guards (`withAuth`, `withAdmin`, `withPresAccess` in `apps/admin/guards`) already fold it in along with role checks:

```typescript
// apps/admin/app/api/members/route.ts
import { RaftResponse } from "@uw-datasci/raft";
import { withAdmin } from "@/guards/withAdmin";
import { profileService } from "@uwdsc/admin";

export const GET = withAdmin(async (_request, _context, user) => {
  const members = await profileService.listMembers();
  return RaftResponse.ok(members);
});
```

## Step 6: Create Client API Functions

Create client-side API wrappers in `apps/web/lib/api/profile.ts`:

```typescript
// apps/web/lib/api/profile.ts
import type {
  UserProfile,
  UpdateProfileRequest,
  UpdateProfileResponse,
} from "@uwdsc/common/types";

/**
 * Get current user profile
 */
export async function getProfile(): Promise<UserProfile> {
  const response = await fetch("/api/profile");

  if (!response.ok) {
    const error = await response.json();
    throw new Error(error.message || "Failed to fetch profile");
  }

  return response.json();
}

/**
 * Update user profile
 */
export async function updateProfile(
  data: UpdateProfileRequest,
): Promise<UpdateProfileResponse> {
  const response = await fetch("/api/profile", {
    method: "PATCH",
    headers: {
      "Content-Type": "application/json",
    },
    body: JSON.stringify(data),
  });

  if (!response.ok) {
    const error = await response.json();
    throw new Error(error.message || "Failed to update profile");
  }

  return response.json();
}
```

## Step 7: Use in Components

Now use the API in your React components:

```tsx
// apps/web/app/profile/page.tsx
"use client";

import { useState, useEffect } from "react";
import { useForm } from "react-hook-form";
import { zodResolver } from "@hookform/resolvers/zod";
import { getProfile, updateProfile } from "@/lib/api/profile";
import { updateProfileSchema } from "@/lib/schemas/profile";
import { Button, Input, Textarea } from "@uwdsc/ui";

export default function ProfilePage() {
  const [profile, setProfile] = useState(null);
  const [isLoading, setIsLoading] = useState(false);

  const {
    register,
    handleSubmit,
    formState: { errors },
  } = useForm({
    resolver: zodResolver(updateProfileSchema),
  });

  // Load profile
  useEffect(() => {
    getProfile().then(setProfile);
  }, []);

  // Handle form submission
  const onSubmit = async (data) => {
    setIsLoading(true);
    try {
      const result = await updateProfile(data);
      setProfile(result.profile);
      alert(result.message);
    } catch (error) {
      alert(error.message);
    } finally {
      setIsLoading(false);
    }
  };

  if (!profile) return <div>Loading...</div>;

  return (
    <form onSubmit={handleSubmit(onSubmit)}>
      <div>
        <label>Name</label>
        <Input {...register("name")} defaultValue={profile.name} placeholder="Your name" />
        {errors.name && <p>{errors.name.message}</p>}
      </div>

      <div>
        <label>Bio</label>
        <Textarea
          {...register("bio")}
          defaultValue={profile.bio}
          placeholder="Tell us about yourself"
        />
        {errors.bio && <p>{errors.bio.message}</p>}
      </div>

      <Button type="submit" disabled={isLoading}>
        {isLoading ? "Saving..." : "Save Profile"}
      </Button>
    </form>
  );
}
```

## Best Practices

### ✅ Do

- Validate all inputs with Zod
- Use TypeScript for type safety
- Wrap every route with `withRaftRoute` (or an admin guard that includes it) and let it handle unexpected errors
- Check authentication/authorization
- Use transactions for multi-step operations
- Add JSDoc comments

### ❌ Don't

- Skip input validation
- Wrap a `withRaftRoute` handler in another `try/catch` - it's redundant, Raft already does this
- Put business logic in API routes
- Access database directly from routes
- Return sensitive data
