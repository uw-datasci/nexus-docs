# Monorepo Structure

A detailed look at the monorepo organization and package relationships.

## Repository Layout

```
uwdsc-website-v3/
├── .github/                # GitHub Actions
├── apps/                   # Frontend applications
│   ├── web/                # Main website and member applications
│   └── admin/              # Admin dashboard and CXC application/review
├── packages/               # Shared packages
│   ├── ui/                 # Design system (@uwdsc/ui)
│   ├── common/             # Shared types and utils (@uwdsc/common)
│   ├── server/             # Backend
│   │   ├── db/            # @uwdsc/db - Postgres, Supabase, BaseRepository, migrations
│   │   ├── core/          # @uwdsc/core - Shared services + Raft HTTP wrapper
│   │   └── admin/         # @uwdsc/admin - Admin-only services
│   ├── eslint-config/      # ESLint configuration
│   └── typescript-config/  # TypeScript configuration
├── scripts/                # Tool scripts (migrate, ui-add, pull-secrets)
├── package.json            # Root package configuration
├── pnpm-workspace.yaml     # Workspace configuration
└── turbo.json              # Turborepo configuration
```

> The documentation site (this site) lives in a **separate repo** (`nexus-docs`), not as an app in this monorepo.

## Apps

### `apps/web` - Main Website

The primary UW Data Science Club website.

**Purpose**: Public-facing website with events, team info, and membership applications

**Tech Stack**:

- Next.js 16 (App Router)
- React 19
- TypeScript
- Tailwind CSS

**Key Features**:

- Home page with events showcase
- Team directory
- Membership application system
- Calendar integration
- User authentication

**Structure**:

```
apps/web/
├── app/                 # Next.js App Router
│   ├── api/             # API routes
│   ├── (auth)/          # Auth pages (login, register, etc.)
│   ├── apply/           # Member application flow
│   ├── calendar/        # Calendar page
│   ├── passport/        # Member passport
│   ├── team/            # Team directory
│   ├── layout.tsx
│   └── page.tsx         # Home
├── components/          # React components
├── constants/           # App constants
├── contexts/           # React contexts
├── hooks/               # React hooks
├── lib/                 # Utilities, API client, services
├── providers/           # React providers
├── proxy.ts             # Next.js 16 request interception (formerly middleware.ts)
├── instrumentation.ts   # Server boot hook - sets RAFT_APP_NAME / RAFT_DATABASE_URL
└── public/              # Static assets
```

### `apps/admin` - Admin App

Admin portal for execs, VPs and presidents.

**Purpose**: Member management, events, support, campaigns, logistics/onboarding, and Recruiting (exec hiring from leadership lock to finalize). See [Recruiting](/admin/recruiting).

**Tech Stack**: Next.js 16, React 19, TypeScript, Tailwind, `@uwdsc/ui`, `@uwdsc/core`, `@uwdsc/admin`, `@uwdsc/db`

**Key Features**:

- Member listing and management
- Recruiting: leadership lock, setup, review board, offers by email link, finalize
- Events, support inbox and email campaigns
- Exec onboarding (logistics)

**Structure**:

```
apps/admin/
├── app/                 # Next.js App Router
│   ├── (admin)/         # Members, recruiting, events, support, campaigns, logistics
│   ├── api/             # API routes
│   ├── login/           # Login page
│   └── unauthorized/    # Unauthorized page
├── components/          # React components
├── contexts/           # React contexts
├── guards/              # withAuth, withAdmin, withPresAccess route guards
├── hooks/               # React hooks
├── lib/                 # Utilities, API client, services
├── providers/           # React providers
└── proxy.ts             # Next.js 16 request interception (formerly middleware.ts)
```

> The documentation site is not part of this repo - it lives in the separate `nexus-docs` repo (Next.js 15, Nextra, MDX), deployed to docs.uwdatascience.ca.

## Packages

### `packages/ui` - Design System

Shared UI components built with shadcn/ui.

**Exports**: `@uwdsc/ui`

**Contents**:

- Button, Card, Input, Select
- Navigation Menu, Tabs
- Dialog, Dropdown, Popover
- Avatar, Badge, Progress
- And more shadcn components

**Dependencies**: Radix UI primitives, Tailwind CSS, Framer Motion, Lucide React icons

**Structure**:

```
packages/ui/
└── src/
    ├── components/      # shadcn/ui components
    ├── hooks/           # useToast, useMobile, etc.
    ├── lib/             # utils (cn, etc.)
    └── styles/          # globals.css
```

### `packages/server/db` - Database & Supabase (`@uwdsc/db`)

Database connection, Supabase clients, and base repository.

**Exports**: `@uwdsc/db` (app-level tsconfig path alias to `config/supabase.ts` - see below), `@uwdsc/db/connection`, `@uwdsc/db/supabase`, `@uwdsc/db/supabase/profile`, `@uwdsc/db/base.repository`

**Contents**:

- Postgres connection (postgres.js, Supabase Transaction Pooler)
- `createSupabaseBrowserClient`, `createSupabaseServerClient`, `createSupabaseMiddlewareClient`
- `BaseRepository` abstract class (repositories extend this and use protected `sql`)
- Migrations (db-migrate; SQL files in `src/migrations/`)

**Structure**:

```
packages/server/db/
└── src/
    ├── config/          # connection.ts, supabase.ts, base.repository.ts
    └── migrations/      # db-migrate SQL and runner
```

**Run migrations from root**: `pnpm migrate`, `pnpm migrate:down`, `pnpm migrate:create`, etc.

> `@uwdsc/db`'s `package.json` doesn't declare a `"."` export - the bare `@uwdsc/db` specifier used in app code (e.g. `import { createSupabaseServerClient } from "@uwdsc/db"`) is resolved by a `paths` alias in each app's own `tsconfig.json`, not by the package's `exports` map.

### `packages/server/core` - Shared Backend (`@uwdsc/core`)

Shared services and repositories used by web and admin apps.

**Exports**: `@uwdsc/core` - service classes and singletons: `profileService`, `applicationService`, `teamService`; `AuthService`, `ResumeService` (create per-request in app `lib/services.ts` via `createAuthService()` / `createResumeService()`). `@uwdsc/core/http` - `withRaftRoute`, the [Raft](/packages/raft) route wrapper used by every `apps/web` API route.

**Contents**:

- **Modules** (`src/modules/<domain>/`), each with a `<domain>.service.ts` and `<domain>.repository.ts`: `auth`, `profile`, `application`, `team`, `events`, `membership`, `file`, `contact`
- `src/http/withRaftRoute.ts` - wraps `withRaft` from `@uw-datasci/raft` with this repo's `ApiError` translation
- Repositories (ProfileRepository, ApplicationRepository, AuthRepository, etc.) extending `BaseRepository` from `@uwdsc/db/base.repository`
- `src/types/`, `src/utils/` - shared types and utilities

**Structure**:

```
packages/server/core/
└── src/
    ├── modules/         # auth/, profile/, application/, team/, events/, membership/, file/, contact/
    │                    #   each: <domain>.service.ts + <domain>.repository.ts
    ├── http/            # withRaftRoute.ts - Raft route wrapper (@uwdsc/core/http)
    ├── types/           # Shared type definitions
    └── utils/           # Shared utilities
```

**Dependencies**: `@uwdsc/db`, `@uwdsc/common`, `@uw-datasci/raft`

### `packages/server/admin` - Admin Backend (`@uwdsc/admin`)

Admin-only services (e.g. profile/member management for admin dashboard).

**Exports**: `@uwdsc/admin` - e.g. `profileService` for member listing/updates

**Used by**: `apps/admin` API routes only

**Dependencies**: `@uwdsc/core`, `@uwdsc/db`, `@uwdsc/common`

**Structure**:

```
packages/server/admin/
└── src/
    ├── modules/         # application/, hiring/, membership/, events/, email/, integration/, raft/
    │                    #   each: <domain>.service.ts + <domain>.repository.ts
    ├── types/           # Admin-specific type definitions
    └── utils/           # Admin-specific utilities
```

> The `raft` module here (`src/modules/raft/`) is the **read side** of the `raft.error_quarantine` table - it powers admin's Optics dashboard. It's separate from `@uw-datasci/raft` itself and from `@uwdsc/core/http`, which writes to that table.

### `packages/eslint-config`

Shared ESLint configuration (flat config, ESM).

**Exports**:

- `@uwdsc/eslint-config/base`
- `@uwdsc/eslint-config/next-js`
- `@uwdsc/eslint-config/react-internal`

**Purpose**: Consistent code style across all packages

### `packages/typescript-config`

Shared TypeScript configuration.

**Exports**:

- `@uwdsc/typescript-config/base.json`
- `@uwdsc/typescript-config/nextjs.json`
- `@uwdsc/typescript-config/react-library.json`

**Purpose**: Consistent TypeScript settings

## Workspace Configuration

### `pnpm-workspace.yaml`

Defines which directories are part of the workspace:

```yaml
packages:
  - "apps/*"
  - "packages/*"
  - "packages/server/*"
```

### `turbo.json`

Configures Turborepo tasks (build order, caching, env):

```json
{
  "tasks": {
    "build": {
      "dependsOn": ["^build"],
      "inputs": ["$TURBO_DEFAULT$", ".env*"],
      "outputs": [".next/**", "!.next/cache/**"]
    },
    "dev": { "cache": false, "persistent": true },
    "lint": { "dependsOn": ["^lint"] },
    "check-types": { "dependsOn": ["^check-types"] }
  }
}
```

## Dependency Management

### Internal Dependencies

Packages reference each other using workspace protocol:

```json
{
  "dependencies": {
    "@uwdsc/ui": "workspace:*",
    "@uwdsc/core": "workspace:*",
    "@uwdsc/db": "workspace:*"
  }
}
```

### Shared Dependencies

Unlike some Turborepo setups, React, Next.js, Tailwind, and similar libraries are **not** hoisted to a single root install here - each app and package declares its own version in its `package.json`. The root `package.json` itself only holds dev tooling (`turbo`, `eslint`, `prettier`, `typescript`) and `dotenv`.

Version consistency across packages is instead enforced centrally via `pnpm-workspace.yaml`'s `overrides`:

```yaml
overrides:
  "@types/react": ^19.2.7
  "@types/react-dom": ^19.2.3
  mermaid: ^11.14.1
  postcss: ^8.5.10
```

### App-Specific Dependencies

Apps can have their own unique dependencies:

- `apps/web`: e.g. SWR, react-feather, babel-plugin-react-compiler
- `apps/admin`: e.g. @tanstack/react-table, sonner

## Build Order

Turborepo automatically determines build order:

1. **Config packages** (eslint-config, typescript-config)
2. **packages/common** (shared types/utils)
3. **packages/ui** (design system)
4. **packages/server/db** (connection, BaseRepository, migrations)
5. **packages/server/core** (depends on db, common)
6. **packages/server/admin** (depends on core, db, common)
7. **Apps** (depend on ui, core, and optionally admin/db)

## Import Paths

### In Apps

```tsx
// UI components
import { Button, Card } from "@uwdsc/ui";

// Shared backend (web and admin)
import { profileService, applicationService } from "@uwdsc/core";
import { createAuthService, createResumeService } from "@/lib/services"; // uses @uwdsc/db + @uwdsc/core

// Raft route wrapper (web routes wrap directly; admin uses guards that fold this in)
import { withRaftRoute } from "@uwdsc/core/http";
import { RaftResponse } from "@uw-datasci/raft";

// Admin-only (admin app API routes)
import { profileService } from "@uwdsc/admin";

// Database / Supabase (when creating services)
import { createSupabaseServerClient } from "@uwdsc/db";
```

### In Packages

```tsx
// In @uwdsc/core or @uwdsc/admin
import { BaseRepository } from "@uwdsc/db/base.repository";
import { sql } from "@uwdsc/db/connection";
```

## Adding New Packages

### 1. Create Package Directory

```bash
mkdir -p packages/my-package/src
cd packages/my-package
```

### 2. Initialize package.json

```json
{
  "name": "@uwdsc/my-package",
  "version": "0.0.1",
  "private": true,
  "main": "./src/index.ts",
  "types": "./src/index.ts"
}
```

### 3. Add to Dependencies

In consuming package/app:

```json
{
  "dependencies": {
    "@uwdsc/my-package": "workspace:*"
  }
}
```

### 4. Install and Build

```bash
pnpm install
pnpm build
```

## Best Practices

### ✅ Do

- Keep packages focused and single-purpose
- Use workspace protocol for internal dependencies
- Follow the dependency direction (apps → packages)
- Share common code in appropriate packages
- Use TypeScript for type safety

### ❌ Don't

- Create circular dependencies
- Have packages depend on apps
- Duplicate code across packages
- Mix different concerns in one package
