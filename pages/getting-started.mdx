# Getting Started

Get your development environment up and running in minutes.

## Prerequisites

Before you begin, ensure you have the following installed:

- **Node.js** >= 24 (see `engines` in root `package.json`)
- **pnpm** 11.x (pinned via `packageManager` in root `package.json`; install through Corepack below)

### Installing pnpm (Corepack)

Use [Corepack](https://nodejs.org/api/corepack.html), which ships with Node.js, to enable the `pnpm` shim on your PATH. This matches the approach described in the Node.js documentation for managing package managers.

```bash
corepack enable
```

On Windows, run the same command in PowerShell or Command Prompt; you may need an elevated shell the first time.

After Corepack is enabled, running `pnpm` inside this repository uses the exact version declared in the root `package.json` `packageManager` field (currently pnpm 11.x) without a separate global install.

To install pnpm 11 globally (for example, before you clone the repo), run:

```bash
corepack install -g pnpm@11
```

Or follow the [official pnpm installation guide](https://pnpm.io/installation).

## Installation

### 1. Clone the Repository

```bash
git clone https://github.com/uw-datasci/uwdsc-website-v3.git
cd uwdsc-website-v3
```

### 2. Authenticate to GitHub Packages

`apps/web` and `apps/admin` depend on [`@uw-datasci/raft`](/packages/raft), UWDSC's private SDK for standardized API responses and error quarantine. It's published to **GitHub Packages** (`npm.pkg.github.com`) under the `@uw-datasci` scope, not to the public npm registry, so `pnpm install` needs a GitHub token before it can resolve that dependency. The repo's committed `.npmrc` only routes the scope to that registry:

```ini
@uw-datasci:registry=https://npm.pkg.github.com
```

The token itself is configured **per machine**, not in the repo (see below).

> **Token type matters**: GitHub Packages' npm registry only supports a **classic** personal access token — [fine-grained tokens are not supported](https://docs.github.com/en/packages/working-with-a-github-packages-registry/working-with-the-npm-registry) for this. Make sure you create the classic kind below.

**Create the token:**

1. Go to [github.com/settings/tokens](https://github.com/settings/tokens) → **Generate new token** → **Generate new token (classic)**.
2. Give it a name (e.g. `uwdsc-packages`) and an expiration.
3. Under **Select scopes**, check only **`read:packages`**.
4. Click **Generate token** and copy it immediately — GitHub won't show it again.

Your GitHub account also needs to be a member of the **uw-datasci** org, or the registry will 401/404 on the package even with a valid token.

**Export it as `NODE_AUTH_TOKEN`** so pnpm can find it. Persist this in your shell profile so it survives new terminal sessions:

```bash
# zsh (default on macOS)
echo 'export NODE_AUTH_TOKEN=ghp_yourtokenhere' >> ~/.zshrc
source ~/.zshrc

# bash
echo 'export NODE_AUTH_TOKEN=ghp_yourtokenhere' >> ~/.bashrc
source ~/.bashrc
```

On Windows (PowerShell), set it for the current session with `$env:NODE_AUTH_TOKEN = "ghp_yourtokenhere"`, or add it as a persistent user environment variable via System Properties → Environment Variables.

**Point your user-level `~/.npmrc` at the variable.** pnpm 12+ refuses to expand `${...}` variables in a repository's `.npmrc` auth settings (you'd see `Ignored project-level auth setting "//npm.pkg.github.com/:_authToken"`), so the auth line has to live in your home directory instead. The single quotes matter: they write the literal `${NODE_AUTH_TOKEN}` reference, so the token itself never lands in the file.

```bash
# macOS / Linux
echo '//npm.pkg.github.com/:_authToken=${NODE_AUTH_TOKEN}' >> ~/.npmrc
```

On Windows (PowerShell): `Add-Content "$HOME\.npmrc" '//npm.pkg.github.com/:_authToken=${NODE_AUTH_TOKEN}'`

You only need to do this once per machine; it covers every UWDSC repo.

> **Never commit your token or add the auth line to a repo's `.npmrc`.** In CI, `actions/setup-node` (with `registry-url`) writes its own user-level credentials, so the committed `.npmrc` only needs the scope line.

Verify the setup before moving on:

```bash
echo $NODE_AUTH_TOKEN                    # should print your token
pnpm view @uw-datasci/raft version       # should print a version, not a 401
```

### 3. Install Dependencies

```bash
pnpm install
```

This will install all dependencies for all packages and apps in the monorepo. Thanks to pnpm workspaces, shared dependencies are efficiently linked.

### 4. Set Up Environment Variables

First, create a `.env` file in the **root directory** of the repository:

```bash
INFISICAL_CLIENT_ID=<insert-id-here>
INFISICAL_CLIENT_SECRET=<insert-secret-here>
```

> **Note**: Contact the Dev VPs on Discord to get your Infisical credentials, or check the DSC exec server for the values.

Then, pull environment variables from Infisical:

```bash
pnpm pull-secrets
```

The `pull-secrets` script will:

- Install the Infisical CLI globally if it's not already installed
- Initialize Infisical configuration if needed
- Authenticate with Infisical (using machine identity or user login)
- Sync environment variables from Infisical for `web` and `admin` apps
- Create `.env.local` in each app directory with the synced secrets

## Running the Apps

### Start All Apps

```bash
pnpm dev
```

This starts both applications in development mode:

- **Web app**: http://localhost:3000
- **Admin app**: http://localhost:3001

> This documentation site lives in a separate repo (`nexus-docs`) and is run from there with its own `pnpm dev` — see that repo's README. Note that it also defaults to port 3000, so don't run it alongside `apps/web` without changing one of the ports.

### Start Specific Apps

If you only want to work on a specific app:

```bash
# Main website only
pnpm dev:web

# Admin app only
pnpm dev:admin
```

## Building for Production

### Build All Packages

```bash
pnpm build
```

### Build Specific App

```bash
pnpm build --filter=web
pnpm build --filter=admin
```

## Common Commands

```bash
# Development
pnpm dev                    # Start web + admin
pnpm dev:web                # Start main website only
pnpm dev:admin              # Start admin app only

# Building
pnpm build                  # Build all packages

# Code Quality
pnpm lint                   # Lint all packages (eslint --max-warnings 0; warnings fail)
pnpm check-types            # Type-check the whole workspace
pnpm format                 # Format code with Prettier

# Secrets & Database
pnpm pull-secrets           # Sync env vars from Infisical into apps/*/.env.local
pnpm migrate                # Apply database migrations
pnpm migrate:down           # Roll back the last migration
pnpm migrate:create <name>  # Scaffold a new migration
pnpm migrate:check          # Check migration status

# UI Components
pnpm ui:add button          # Add shadcn button component to @uwdsc/ui
pnpm ui:add form            # Add shadcn form components to @uwdsc/ui
```

## Troubleshooting

### Port Already in Use

If you get an error that a port is already in use, you can either:

1. Kill the process using that port
2. Change the port in the app's `package.json` dev script

### `401 Unauthorized` / `E401` Installing `@uw-datasci/raft`

This means pnpm couldn't authenticate to GitHub Packages. Check, in order:

1. `~/.npmrc` contains `//npm.pkg.github.com/:_authToken=${NODE_AUTH_TOKEN}`. If `pnpm install` prints `Ignored project-level auth setting`, the auth line is still in a repo's `.npmrc` instead — move it to `~/.npmrc` (see [Authenticate to GitHub Packages](#2-authenticate-to-github-packages)).
2. `NODE_AUTH_TOKEN` is set in **this shell** — run `echo $NODE_AUTH_TOKEN` (a new terminal won't have it unless it's in your shell profile; see [Authenticate to GitHub Packages](#2-authenticate-to-github-packages)).
3. The token is a **classic** PAT, not fine-grained — GitHub Packages doesn't accept fine-grained tokens.
4. The `read:packages` scope is checked on the token.
5. The token hasn't expired or been revoked — `curl -s -o /dev/null -w "%{http_code}\n" -H "Authorization: token $NODE_AUTH_TOKEN" https://api.github.com/user` should print `200`.
6. Your GitHub account is a member of the `uw-datasci` org.

Note that `pnpm install` can succeed with a bad token when the lockfile is up to date and the package is already in your store; `pnpm view @uw-datasci/raft version` always hits the registry.

Then retry:

```bash
pnpm store prune
pnpm install
```

### pnpm Installation Issues

If you encounter other issues with pnpm, try:

```bash
# Clear pnpm cache
pnpm store prune

# Reinstall dependencies
rm -rf node_modules
rm pnpm-lock.yaml
pnpm install
```

### TypeScript Errors

If you see TypeScript errors, try:

```bash
# Clean and rebuild
rm -rf apps/*/.next
pnpm install
pnpm build
```
